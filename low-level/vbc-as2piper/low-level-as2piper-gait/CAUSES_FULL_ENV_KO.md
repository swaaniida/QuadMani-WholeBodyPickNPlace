# VBC 동일 환경 보상 비교: 확인한 원인과 남은 검증

학습 환경은 기존 AS2 VBC 포트의 rough trimesh·전체 DR·6144환경·random EE·reset·command schedule·PPO를 유지한다. AS2 질량·길이 비례값을 사용한다. B1 원본과 AS2 원복판은 수정하지 않는다. [실행 조건·재개 이력](experiments/gait_reward_proxy_v2/PROTOCOL_KO.md), [최신 평가표](experiments/gait_reward_proxy_v2/RESULTS_KO.md)를 기준으로 판단한다.

## 확인한 코드 및 측정 문제

| 항목 | 근거 | 수정 및 해석 |
|---|---|---|
| 발 속도 갱신 누락 | tensor advanced indexing 결과는 복사본이며 기존 값이 초기 상태에 머묾 | PhysX refresh 후 현재 발 속도를 다시 선택. 수정 단독으로 안정적 보행을 입증하지는 못함 |
| feet_jerk가 항상0 | 이전 wrench를 확인하는 객체와 저장하는 객체가 다름 | 같은 객체에 이전 값을 보관. 접촉력 변화는 발 링크 wrench 변화이며 실제 GRF와 구분 |
| 정지 접촉 목표0.5 | AS2 포트의 부호 보정 후 네 발 접지가 penalty가 됨 | 정지 목표를 네 발 모두1로 변경. force penalty0. 단독 보행 개선 효과는 부족 |
| 전진 보상 포화 | 기존 함수는 목표보다 빠른 속도도 같은 최고값 | 대칭 Gaussian으로 과속·저속을 모두 구분. 평지 비교에서 과속 감소 |
| world-z 기반 앞발 높이 | 앞발2개 world-z의 norm은 발별 지면 clearance가 아님 | 네 발의 위상별 지면 기준 높이로 변경. rough에서는 기준 높이와 목표 손실을 추가 비교 중 |
| 체공시간과2Hz 위상 불일치 | 원래 앞발2개·0.5초 기준. 2Hz/duty0.5의 swing은0.25초 | 네 발·0.25초, credit 상한, weight2→0.5 |
| home 근접 유인 | walking_dof는 실제 이동이 아니라 초기 관절 자세 근접도 | weight1.5→0.5. 이 항이 크다고 보행이 잘 되는 것이 아님 |
| triangle-mesh contact force 보고 누락 | SDK 문서, 평지 중량비≈1.0/rough 보고값≈0.30, 실제 메시 근접 접촉 검사 | 기존 관측용 contact bit를 force shaping 입력으로 비교. 센서/관측/물리는 유지. 정상반력 N을 복원한 것이 아님 |

센서 flag 변경 및 새 contact filter는 측정 결과가 부족하여 채택하지 않았다. 기본 물리 소스 `manip_loco.py`는 보존한 원복판과 같다. contact bit 입력으로 바꾼 것만으로 보행 개선이 입증되지는 않았다.

| 높이 기준만 변경하면 해결 | ground 후보301회: 전진0.039/목표0.25m/s, 회전0.122/목표0.6rad/s | 높이 기준 변경 단독으로 충분한 추종이 나오지 않음 |
| 진행 방향 유인 부족 | 강화 후보201→301→401회 전진0.164→0.193→0.226m/s | 이동은 증가하나 넘어짐39→47→63회. 속도 증가를 안정화로 해석하지 않음 |
| 회전 추종 유인 부족 | 강화 후보401회 회전0.237/목표0.6rad/s; 전진 중 yaw MAE0.369rad/s | 같은301회 비교에서 전진 중 yaw MAE0.360→0.254, 넘어짐47→32.401회도 추종·안정성 기준은 미충족 |
| rough에 과도한 swing 높이 감점 | 4cm 대칭 목표가7–11cm 실제 발 들림도 감점. 기록 궤적의 높이 기준/손실 반사실 계산 | ground_floor301회 넘어짐72회로 control47회보다 악화. 채택하지 않음 |

raw body contact force도 SDK 보고 문제를 받을 수 있다. 그 값이0이라는 사실만으로 몸통 무접촉이나 실물 안전성을 보증하지 않는다.

모든 분기는 물리 환경을 재초기화한다. 정적 지형·질량·CoM·마찰·모터 해시가 같더라도 reset·push·EE의 모든 난수 경로와 GPU 물리까지 같다는 뜻은 아니다. warm start 분기를 scratch 성공으로 표시하지 않는다.

## 채택 기준

평균 전진속도만 보지 않는다. 명령별 속도 MAE, 회전 중 전진 이탈, 옆 방향 속도, roll/pitch, 전체20초의 종료, 실제 메시 기준 발 들림·미끄러짐, 정책 재생 영상을 함께 확인한다. 서 있는 모델을 성공으로 분류하지 않는다. 평지·명목 조건 평가는 원인 진단이며 full-environment 통과를 대신하지 않는다.

실험은 W&B 비활성 상태이며 기존 온라인 PID512627과 별개다. 후보 통과와 scratch 학습 검증 전에는 새45000회 production run을 시작하거나 공개 기본 보상을 최종 검증 버전으로 표시하지 않는다.

## 추가 확인: 작은 명령에서 새 진행도 항의 문제

추가했던 constant progress mix는0.001 부근에서 불연속이 있었고 작은 명령에서도 빠른 이동을 상당히 보상했다.401회 정책은 명목 평지에서도 제자리 회전 시0.435m/s로 전진했다. 작은 command에서 mix를0으로 부드럽게 줄이는 수정은 실제 함수 수치 검사를 통과했다. 기존 command 생성 범위를 좁히지 않았다.

현재 `smooth_yaw4`와 `smooth_yaw4_contactmatch`를 모두0에서 시작했다. 새 두 run의 차이는 필요한 stance 접촉이 빠졌을 때의 감점 하나다. 높이 그룹은 동일하게 유지했다. 초기화·환경 동일성은 `matched_fresh_v3.json`, 실제 소스는 `source_snapshots/`에 기록했다. 새 후보의 실제 보행은 학습·holdout·geometry 평가를 통해 판단하며, 수식 검사만으로 통과 처리하지 않는다.
