# 미적용 Foot Lift 제안 및 결정 근거

다음 내용은 분석 결과이며 현재70N 학습 코드에는 적용하지 않았다.

```
R_lift = -lambda * m_stop * tanh(max(h_max - 0.005, 0) / 0.04)
```

h_max는4발 최대 발바닥–지면 간격이다. 현재구조(max+tanh)를유지하는후보분석을진행했다.

## 기존45k 로그에 대한 가상 계산

평지,속도명령0,EE이동,DR/pushOFF.8환경×12~60초(2401틱/환경). RR평균27.66mm/P9545.20mm,항상가장높은발이었다.

|Scale|평균weighted|P05|중앙값|P95|환경당누적/100|
|---|---:|---:|---:|---:|---:|
|−0.1|−0.04912|−0.07637|−0.05157|−0.01819|−1.1793|
|−0.15|−0.07368|−0.11455|−0.07735|−0.02728|−1.7690|
|−0.2|−0.09824|−0.15273|−0.10313|−0.03637|−2.3587|
|−0.3|−0.14736|−0.22910|−0.15470|−0.05456|−3.5380|

−0.2를검증시작후보로권고했으며최적scale학습실험은아니다.15~50mm구간에서유의미한변화가있고약78.3mm에서최대비용95%로포화한다.80mm를0.2초유지하는예의누적비용은−0.01908(/100후)로짧은회복step도완전히면제하지않는다.

max는최고발이하의다른발개선을즉시구분하지못하고5mm이내무부하발도0비용이다.4발유효하중을보장하지않는다. 이미−lambda를곱한함수에또음의scale을곱하면양의보상이되므로부호를한번만적용해야한다.

## Rough 계산의 미해결 문제

- 현재3node최소height는진짜support surface가아니다.30°접지구의위치/5mm양자화예에서가짜간격28.05mm,−.2비용약−.104가발생할수있다. 기하예와실제PhysX rollout측정은구분한다.
- 실제collision mesh의upward-support triangle에대한최근접거리에서반경.028을빼는방식이유력하다.벽측면/위쪽면/edge/penetration을접지로악용하지않도록분리해야한다.
- 6144×4=24576발,K32~128후보면약79만~315만triangle query/정책tick.정점좌표를모두펼치면약28~113MB.성능측정값이나학습속도보장수치가아니다.
- 기존feet-height reward까지임의로바꾸지말고전용helper를검토한다.정확한지형간격검증이전에는제안reward를현재rough학습에그대로적용하지않는다.

0.5초per-foot최소높이 GroundProximity/접촉비율0.6 ValidContact는별도제안으로남아있다.외란회복step허용/기준scale은사용자검토후결정할항목이다.
