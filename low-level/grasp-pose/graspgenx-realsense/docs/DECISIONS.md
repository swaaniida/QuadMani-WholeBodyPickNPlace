# Decisions and verification boundaries

- Tracking integration: reuse official Tracking_SAM `main_tracker`, SAM ViT-H predictor and `aott.aot_segmenter` memory propagation at commit d5e5e81a361dce4ddbe3264a2b8027b2b43ea3fd. Separate `.venv-tracking` (torch 1.13.1+cu117, torchvision 0.14.1) from existing GraspGenX `.venv` (torch 2.5.1+cu121). All new files remain under grasp-pose. GroundingDINO and correlation CUDA extensions were built for SM80 with two build jobs; system CUDA/driver unchanged.
- Official demo verification: run the original `demo.py main()` with only GUI click/display automated on headless astrago. The click is inside the official first-frame annotation; the actual SAM prediction initializes AOT. 82 genuine DAVIS frames, 81 VOS propagation steps; first SAM IoU 0.9700; no GT mask injected into AOT.
- Streaming design: Windows sends one JPEG + lossless depth + actual scale/K + frame/session/sequence payload to localhost-5557 over SSH. Server stores at most eight matched snapshots. One asynchronous grasp job calls existing localhost-5556 `infer_scene_depth`; tracking continues. Reset changes generation and invalidates old results. Latest-frame worker drops intermediate captures and never creates an inference backlog.
- Safety of data association: initialize from the exact clicked displayed frame, propagate masks only through the official VOS engine, latch geometric mask loss, reject stale/non-latest/invalid-depth/old-session snapshots for G. These heuristics do not prove semantic identity or physical grasp safety. Nonzero depth-frame distortion is rejected for the pinhole scene-depth route rather than silently using wrong geometry.
- Verification boundary: actual moving DAVIS sequence tests temporal VOS; actual recorded RGB-D repeated as a labeled static replay tests the two-service pipeline, G while tracking, reset and text initialization. The exact Windows networking worker also passes against the real services in a torch-free environment with recorded replay. This does not satisfy live D435i hardware/Windows GUI/SSH latency acceptance; run the supplied client on Windows to complete it.

- 2026-11-11 relocation: After the user granted write access, moved the entire project to `/data/team/users/suhwan/grasp-pose/graspgenx-realsense`, including the Python runtime and both virtual environments. The latest user instruction authorizes restarting the server and forbids compatibility symlinks at the previous location. Preserve the existing parent README and robot projects. Historical benchmark logs retain their original paths as evidence of those runs.
- Physical GPU is A100 80GB with MIG 3g.40gb (40192 MiB), 42 SMs. Driver 535.161.08; system toolkit 11.7. Use isolated torch 2.5.1+cu121 eager inference. Do not update system driver/toolkit or use CUDA 13 fast-inference extras.
- Official commit `44eb1d77d6d27bc97ee361e3afb717a2115e30a9`. Use official model/planner/server implementation. Official name-based `infer` does not select a planner; it invokes diffusion. Use exported official `franka_umi` sweep parameters with `infer_object` for GraspMoE/diffusion comparisons.
- Download pinned official Hugging Face snapshots through huggingface_hub because git-lfs is absent. No checkpoint or gripper conditioning is invented. Complete franka_umi assets are fetched; other grippers are outside this initial installation.
- Default official bind is 0.0.0.0. Both provided server commands explicitly bind to 127.0.0.1. Measured server subclasses official server and adds CUDA-synchronized complete-handler timing and allocator peaks; it reuses checkpoint loading, samplers, protocol and dispatch.
- Camera frame is optical (+x right, +y down, +z forward). Output is T_camera_gripper_base; never a robot TCP command. GraspMoE analytic branch's world-Z heuristic is interpreted in this camera frame; no gravity alignment is assumed.
- Remote Linux cannot validate USB capture or Windows GUI operation. Geometry and protocol checks can run here; hardware/UI checks must remain marked pending until Windows execution.

Exact observations are in outputs/benchmarks/*.json and REPORT.md.
